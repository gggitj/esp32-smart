## 1. 项目定位

“啸天”是 ESP32-S3 模块化终端项目中的可配置红外围界模块。通过调整探头位置和组合方式，在家门口形成通行检测组，在户外形成直线、折线或闭合警戒区，将遮挡、通行及可检测的设备异常状态显示到树莓派 / Orange Pi 终端。方向与速度估算需要专门的双检测线布局，不能仅靠任意两条边的时间差实现。

当前用户已确定：

- 模块名：啸天。
- 核心方向：优先使用红外线。
- 使用场景：希望可以在野外真正做成类似栅栏的红外线报警器。
- 当前硬件：尚未购买传感器、执行器或专用模块。
- 控制板：当前 ESP32-S3 板是全新的，也可以更换板子。
- 供电：需要同时考虑直接供电和独立供电。
- 告警方式：先在终端显示，不先做本地蜂鸣器、继电器或远程推送。
- 文档位置：独立放在本模块目录中。
- 作品定位：大学生团队作品，新增采购预算上限 250 元，优先复用现有板和终端。
- 当前场景：家门口通行方向和速度估算；户外直线、折线及闭合区域的分段触发监测。
- 布局需求：可移动支撑点、调整间距和折角，不要求正方形；10×10 m 为期望场景示例，实际边长与性能待确认和测试。
- 安装形态：立柱为可单独选配的安装附件，核心设备不依赖专用立柱；可按现场固定在门框、墙面、栏杆等已有物体上。
- 此前提出的一段 3–5 m 报警线仅可作为单边实验，不能代替用户现在明确要求的完整围界。

本阶段原则：不要假定具体传感器型号，不写死 GPIO，不提前承诺实机效果。

## 2. 系统边界

本项目已有控制面和业务面分离的架构，啸天必须沿用这个边界：

- 控制面：LinkIt / PBR1 只负责模块接入、拔出、控制桥事件，不承载红外告警业务数据。
- 业务面：啸天的布防状态、遮挡状态、告警事件、心跳、电源状态和配置命令走 BLE 或固定 Pi 热点 LAN 的业务数据面。
- 插件包：终端侧页面仍按 module-devkit 的 manifest、QML、ARM64 插件、签名包机制发布。

对组员的实现要求：

- ESP32-S3 侧读取传感器并发布状态 JSON。
- 终端插件解析 JSON，显示啸天页面和告警历史。
- 如果未来增加蜂鸣器、警灯或继电器，也应作为 ESP32 侧执行器，并通过业务命令控制。

## 3. 硬件路线建议

### 3.1 首选路线：主动对射红外

为了做“真的像栅栏”的报警器，首选主动对射红外，也就是一端发射红外光，另一端接收红外光。有人或物体穿过时，光束被遮挡，接收端输出触发信号。

优点：

- 更符合“红外栅栏”的产品形态。
- 可以拉开距离，适合门口、通道、院子边界。
- 触发逻辑清楚：光束正常 / 光束被遮挡 / 设备故障或断线。
- 适合终端显示成“已布防 / 被遮挡 / 离线 / 故障”。

采购时优先看这些参数，而不是先看品牌：

- 发射端和接收端是分体式。
- 查看厂家明确标注的户外额定距离，不能把室内距离当成户外距离。按现场环境留余量，并通过实测确认；不能仅凭标称距离倍数承诺可用距离。
- 适合户外或半户外，外壳至少防水防尘，安装后能遮光、防雨。
- 输出最好是继电器干接点、NPN/PNP 开集电极或清晰的数字输出。
- 供电电压清楚，例如 5 V、12 V 或 24 V。
- 有对准指示、灵敏度调节或状态灯会更方便调试。

ESP32 接入建议：

- 优先选择继电器无源干接点，使用 ESP32 侧 3.3 V 上拉读取，触点本身与传感器电源电路隔离；短线样机可不另买光耦板。开集电极输出需另核对电压、接地和接口，不能当作干接点接线。
- 可接受：传感器输出 5 V 数字量，但必须做分压、光耦或电平转换后进入 ESP32 3.3 V GPIO。
- 不建议：把 12 V / 24 V 输出直接接 ESP32。
- 野外长线建议做光耦隔离、TVS、防反接和滤波，避免雷击感应、静电和长线毛刺。

### 3.2 备选路线：裸红外 LED + 接收管

裸红外发射 LED 和接收管适合学习和短距离实验，但不建议作为野外第一版。

风险：

- 强阳光会严重干扰。
- 需要调制、解调、光学结构、遮光筒和滤波。
- 对准和距离稳定性难控制。
- 防水、防尘、昆虫遮挡和机械安装都要自己解决。

如果组员想做底层学习，可以作为桌面验证分支，但不应作为第一个野外交付方案。

### 3.3 不作为首选：反射红外和 PIR

反射红外适合近距离检测物体靠近，不适合做远距离栅栏线。PIR 人体红外适合检测人活动，但不是一条明确的栅栏线，无法可靠判断“穿过某一道边界”。

这两类可以做辅助传感器，但不作为啸天第一版主传感器。

## 4. 供电方案

啸天需要考虑直接供电和独立供电。250 元版本优先用适配器直供，也可用借来的充电宝加升压模块演示独立供电；两端允许通过低压线共用电源，不要求各自配电池。

### 4.1 直接供电模式

适合桌面调试、固定安装和长期测试。

推荐第一阶段使用：

- ESP32-S3 由 USB 或稳定 5 V 供电。
- 红外对射传感器按自身要求供电，例如 5 V / 12 V / 24 V。
- 如果传感器和 ESP32 不隔离，必须共地。
- 如果用继电器干接点或光耦隔离，可以减少地线干扰问题。

注意：

- ESP32 GPIO 只能接受 3.3 V 逻辑。
- 传感器外部供电不能反灌 ESP32。
- 直接供电模式下先不做低功耗，只保证稳定采样和告警。

### 4.2 独立供电模式

当前优先用于短时户外演示，采用已有或借来的成品充电宝，不采购裸电芯、专用电池包或太阳能套件。

- 充电宝 5 V 经匹配的 5 V 转 12 V 升压模块给两个对射端供电，两端通过低压电源线连接。
- ESP32 可以由充电宝稳定的 5 V 支路供电，按开发板的供电接口接入。
- 确认两端电压范围、最大总功耗、升压模块持续输出能力、线缆压降，以及充电宝是否自动关机。
- 使用充电宝时保持与外接适配器二选一，未经电源切换设计不要把两路输出并接。
- 如果无法借到充电宝，先完成直供版，独立供电保留待办；不要默认 250 元内已经包含新购充电宝。
- 未来如有长期部署需求，再评估成品电池包、容量和太阳能，不纳入本轮采购。

第一版不要承诺续航。组员需要先记录：

- ESP32 工作电流。
- 传感器发射端电流。
- 接收端和隔离电路电流。
- Wi-Fi / BLE 连接时的峰值电流。
- 电池容量和实测运行时间。

## 5. 初版功能范围

第一版只做必要功能，目标是让组员能快速完成硬件闭环。

必须有：

- 多段配置：为检测段设置名称、相邻关系和工作模式；具体协议待设计。
- 实时显示：光束正常、遮挡告警、离线、故障。
- 布防状态：armed / disarmed。
- 触发计数：本次上电后的告警次数。
- 最近一次触发时间：由终端侧记录显示。
- 心跳：ESP32 定期发布状态。
- 输入去抖：避免树叶、毛刺或接触不良造成连续刷屏。
- 告警保持：短暂遮挡后至少保持一段时间，终端能看清。
- 通行模式目标：两条已标定平行检测线判断方向，并在有效单人通行条件下估算平均通过速度；不能从任意两段边界的事件时间差直接测速。

暂不做：

- 本地蜂鸣器。
- 本地继电器。
- 手机推送。
- 摄像头联动。
- 多光束精确定位。
- 自动报警拨号或安防级联。

## 6. 数据协议草案

业务数据由 ESP32-S3 发布给终端。底层仍使用 module_data_service 的 session、seq、CRC 和认证机制；插件收到的是 decoded payload。

本节保留的是早期单路数据草案。第 16 节新增的多段、布局、采集时间和通行事件尚未合入此 JSON，不能直接以本节宣称已支持多防区或测速。

### 6.1 ESP32 发布 payload

建议第一版 payload：

```json
{
  "source": "xiaotian",
  "schema": "xiaotian.v1",
  "heartbeat": 123,
  "armed": true,
  "beam_clear": true,
  "alarm": false,
  "tamper": false,
  "sensor_online": true,
  "trigger_count": 0,
  "input_level": 1,
  "hold_ms": 1500,
  "debounce_ms": 80,
  "power_source": "direct",
  "battery_V": null,
  "battery_pct": null,
  "rssi": null,
  "fault": null
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `source` | 固定为 `xiaotian`，方便终端识别 |
| `schema` | 协议版本，第一版为 `xiaotian.v1` |
| `heartbeat` | ESP32 侧递增计数 |
| `armed` | 是否布防 |
| `beam_clear` | 光束是否正常 |
| `alarm` | 当前是否告警 |
| `tamper` | 防拆、断线或遮挡异常，第一版可先固定为 false |
| `sensor_online` | 传感器是否在线，数字输入传感器第一版可先固定为 true |
| `trigger_count` | 本次上电后的触发次数 |
| `input_level` | 原始 GPIO 电平，方便调试接反 |
| `hold_ms` | 告警保持时间 |
| `debounce_ms` | 输入去抖时间 |
| `power_source` | `direct` / `battery` / `unknown` |
| `battery_V` | 独立供电并有电量检测时填写，否则 null |
| `battery_pct` | 独立供电并有电量检测时填写，否则 null |
| `rssi` | 需要时再填 |
| `fault` | 无故障为 null，有故障时填短字符串 |

### 6.2 终端下发命令

建议第一版命令：

```json
{"command":"set_armed","armed":true}
{"command":"set_hold_ms","hold_ms":1500}
{"command":"set_debounce_ms","debounce_ms":80}
{"command":"reset_count"}
{"command":"request_status"}
```

命令规则：

- 所有参数必须范围校验。
- 未识别命令返回错误状态，不应重启模块。
- `set_armed=false` 后，ESP32 可以继续发布 `beam_clear`，但 `alarm` 应为 false。
- `request_status` 立即发布一帧完整状态。

## 7. 终端页面草案

页面名称：啸天。

建议显示区域：

- 顶部状态：已布防 / 未布防 / 告警 / 离线。
- 主状态图标：光束正常、光束被遮挡、传感器故障。
- 实时字段：触发次数、最近触发、供电方式、电池状态。
- 控制项：布防开关、清零计数、告警保持时间、去抖时间。
- 调试折叠区：原始输入电平、heartbeat、fault、最近 payload 时间。

页面原则：

- 不伪造历史数据。
- 没有电池检测硬件时显示 `--`，不要推断电量。
- 传感器未定型前，页面文字使用“光束”而不是具体型号。

## 8. GPIO 和电气接口待确认

现在不写死引脚。等传感器和板子确定后再填写：

| 用途 | 方向 | 候选接口 | 当前状态 |
| --- | --- | --- | --- |
| 红外告警输入 | 输入 | GPIO 数字输入 | 待确认 |
| 传感器电源使能 | 输出 | GPIO / MOSFET | 可选 |
| 本地指示灯 | 输出 | GPIO PWM | 可选 |
| 本地蜂鸣器 | 输出 | GPIO PWM | 暂不做 |
| 电池电压检测 | 输入 | ADC / MAX17048 | 独立供电阶段再定 |
| 防拆输入 | 输入 | GPIO | 第二版再定 |

必须遵守：

- 不使用 ESP32-S3 启动绑带脚，除非确认启动电平安全。
- 不把超过 3.3 V 的信号接到 GPIO。
- 户外长线输入要先经过保护和隔离，再进 ESP32。
- 传感器和 ESP32 供电不同源时，先决定是否共地或隔离。

## 9. module_id 和传输模式

待确认项：

- `module_id`：未定。必须在 1-255 范围内，并且不能与已有模块冲突。
- 模块实例名：建议 `xiaotian-<board-mac-or-short-id>`。
- 传输模式：建议第一版使用固定 Pi 热点 LAN，便于插件包和持续状态；如果只做小数据也可以 BLE。
- 签名：沿用平台现有签名链，不生成新的公钥替换目标 Pi。

已有 registry 里出现过的 ID：`0x04`、`0x05`、`0x09`、`0x14`、`0x15`、`0x16`、`0x17`、`0x50`。啸天不要占用这些值。

候选建议：先预留 `0x19`，但必须由项目负责人确认后再写入 manifest 和固件。

## 10. 开发步骤

### 阶段 A：需求冻结

组员需要确认：

- 目标检测距离：例如 3 m、5 m、10 m、20 m。
- 安装环境：树林、院子、门口、走廊、阳台、棚内。
- 是否日晒、雨淋、雾气、灰尘、昆虫多。
- 需要一束光还是多束光。
- 是否允许误报，还是宁可漏报少一点。
- 直接供电的电压来源。
- 独立供电希望续航多久。
- 是否需要防拆和断线检测。

### 阶段 B：采购与桌面验证

先买一套主动对射红外发射端 + 接收端，以及必要供电和电平转换材料。

桌面验证目标：

- 万用表确认输出在遮挡 / 未遮挡时的状态。
- 确认输出电压不会伤 ESP32。
- 用临时 GPIO 程序读取稳定电平。
- 记录遮挡响应时间和抖动。
- 记录传感器最小、最大可用距离。

### 阶段 C：模块工程初始化

确认 module_id 后再执行：

```sh
python3 module-devkit/module_devkit.py init module-devkit/examples/xiaotian \
  --module-id <待确认ID> --name "啸天"
```

注意：当前目录已有本交接文档。如果需要使用 `module_devkit.py init`，要么将文档临时移出，要么手工按 template 补齐工程文件。

### 阶段 D：固件实现

ESP32 侧实现：

- GPIO 输入初始化。
- 去抖状态机。
- 布防状态。
- 告警保持。
- 心跳发布。
- 命令解析和参数校验。
- 直接供电 / 独立供电字段。

### 阶段 E：终端插件实现

Pi 插件实现：

- `pi_module_on_data()` 解析 `xiaotian.v1`。
- QML 页面显示状态。
- 布防、清零、参数设置动作。
- 最近告警时间由终端本地记录。
- 插件停止时同步停止线程和定时器。

### 阶段 F：实机验收

验收记录必须写回本文档或同目录 `VALIDATION.md`：

- 传感器型号和输出类型。
- 实际接线图。
- ESP32 板型和 GPIO。
- 供电电压和电流。
- 测得检测距离。
- 强光、夜晚、雨雾或遮挡测试结果。
- 误报 / 漏报场景。
- 固件 commit / 包 SHA256。
- 哪些项目没有测试，必须标 `NOT TESTED`。

### 14.4 独立供电如何控制成本

**借一只已有充电宝，加一只 5 V 转 12 V 升压模块，集中给整套装置供电。** 发射端和接收端用低压线连接即可，独立供电不等于两端必须各有一套电池。

```text
直供：
12 V 适配器 ─┬─ 发射端（低压电源线延伸到另一侧）
             ├─ 接收端
             └─ 12 V→5 V 稳压 ─ ESP32

独立供电：
借用充电宝 5 V ─┬─ 5 V→12 V 升压 ─┬─ 发射端
                │                  └─ 接收端
                └─ 稳定的 5 V 支路 ─ ESP32
```

这两种接法是替换使用，不能直接并接电源。独立供电时保留适配器用于桌面调试也可以；新增升压模块目标约 10–20 元，可从 35 元机动费用中支付，前提是其实际持续功率满足负载。

充电宝按已有或借用计价，**不含新购充电宝，也不含终端和热点的电池供电**。借不到时，先交付直供演示，文档将独立供电标为待验证，不能写成已经实现。

## 15. 开放场地电子栅栏与 GitHub 参考

### 15.1 当前确认的使用场景

用户希望监测开放场地的边界，形成真正的电子警戒围界，而不只是监测一个入口。当前先讨论场景与技术路线，暂不考虑预算约束；此前的 250 元草案仍保留用于后续核算。

在普通主动直射红外方案下，一对发射 / 接收端形成一条直线警戒段。围成三角形通常需要三条光路，围成长方形通常需要四条光路；四边完全开放时，一两对通常无法独立覆盖完整周界。

以长方形为例，建议四边独立检测。四个角各布置一个朝向下一条边的发射头和一个接收上一条边的接收头，可以安装在四个支撑点上，共四对光学探头。控制板不一定需要四块：初版可用一块 ESP32 读取四路接收输出，前提是接线距离、供电和电气接口适合。

如果已有墙体等不可绕行的实体边界，可只对开放边补光路。电子栅栏负责越界告警，不形成物理阻拦；单一高度仍可能被跨越或钻过，多高度光束应作为另一个设计维度评估。

## 16. 最新场景定义：可调整布局的红外围界

### 16.1 已确认的产品方向

用户希望同一套设备适用于家门口和野外：

- 家门口可增加探头数量，根据先后触发和时间差判断通行动向、估算通过速度。
- 野外可监测一条直线、一串折线或一个区域的周界，显示具体哪一段触发。
- 支撑点间距与形状可按现场调整，不限制为正方形；10×10 m 是场景参考，尚不是已通过的规格。
- 当前“可拉伸”按挪动探头 / 支撑点后重新对准、更新配置理解。是否需要伸缩杆、收线机构、实时移动对准或自动测距，尚未提出和确认。
- 立柱由用户明确为独立选配件。本文“端点 / 支撑点”表示光学安装位置，不要求每个位置都有立柱。

建议对外描述：**“啸天：支持通行方向与速度估算、可配置直线 / 折线 / 闭合区域的模块化红外警戒系统。”** 该描述是目标，不表示功能已完成。

### 16.2 三种模式共用检测段

| 模式 | 典型布局 | 最少检测段 | 输出内容 |
| --- | --- | --- | --- |
| 直线警戒 | 一对探头跨过一条路径或边界 | 一段 | 遮挡、恢复、触发次数和时间 |
| 折线 / 区域警戒 | 多段首尾相邻，按场地形成开口折线或闭合多边形 | 折线通常两段起；闭合三角形三段、矩形四段 | 哪一段触发、事件顺序、各段与整体状态 |
| 通行方向 / 速度估算 | 沿行进方向前后布置两条平行检测线 | 两段，即两对普通对射探头 | 有效通行方向、两线时间差、平均通过速度估计 |

这里的“一段”是一条可独立读取的光路。商品所称双光束如果只有一路汇总输出，通常仍算一个检测段；不能将它直接视为两条独立测速线。

### 16.3 家门口：动向与速度如何定义

两条检测线应位于同一通道的前后位置，沿主要行进方向分隔，布置高度和触发条件尽量一致。例如：

```text
门外 → 检测线 A → 已测间距 d → 检测线 B → 门内
```

当同一次有效通行先触发 A、再触发 B，可定义为进入；先 B 后 A 定义为离开。只触发一条、超时、折返、多人混行或无法可靠配对的事件，应标为未完成 / 不确定，不强行给出速度或人数。

基本计算为 `v = d / |tB - tA|`。这里 d 是两条平行检测线的垂直间距，不是单条光束的跨度，也不是场地边长。

仅作计算示例：两线间距 0.8 m、两次触发间隔 0.5 s，得 1.6 m/s。在基本沿通道垂直穿越检测线时，可解释为区间平均通过速度估计；斜穿时计算的是垂直于检测线的平均速度分量，不等同于实际行走轨迹的速度大小。

该功能不提供瞬时速度、人员身份或场地内连续轨迹。人体轮廓、手臂摆动、探头响应、输入去抖和间距测量都会影响结果，需要校准后报告误差。

### 16.4 户外：自由组合边界

每个直线检测段关联两个端点，端点可以设置名称和相对位置；多段组合成场地布局。移动支撑点后重新对准，并更新必要的间距或布局参数。普通探头仍要求直视，任意折角通过新增直线段形成，不自动绕角。

拐点可将“上一段的接收头”和“下一段的发射头”安装在同一固定位置，两头分别调整朝向。能否如此安装须结合探头转角、光轴和近邻串扰验证；不能据此减少所需光学通道。固定位置可以是现有结构或选配立柱。

区域模式下，终端显示触发边段和事件先后；仅由一层边界线，无法判断区域内部的完整运动轨迹。两条任意折线上的触发位置通常未知，不能用端点距离或两次上报间隔直接计算人的速度。需要方向 / 速度时，在关注位置增加已标定的双线通行组。

### 16.5 时间采集与终端显示要求

测速应使用同一次通行中两路输入在设备侧采集的时间，不能使用终端收到 Wi-Fi / BLE 报文的时间，也不能使用告警保持结束时间。

- 初版双线组优先由同一块 ESP32 采集，使用同一单调时钟，避免跨节点时钟偏差。
- 使用符合输入稳定判据的遮挡边沿时间，记录去抖和滤波方法；告警保持只影响显示，不延后原始事件时间。
- 若以后由两块独立设备采集，需设计时钟对齐、误差界限、事件配对和掉线处理，不能直接相减两台设备的本地计时值。
- 商用对射头的遮挡判定时间和继电器延迟需核实；满足告警用途，不一定能提供足够稳定的测速时间。
- 通道极性、响应时间、多光束汇总逻辑与邻段串扰都要纳入验证。

建议界面：布局图与分段状态、事件列表、通行方向、平均速度估计以及“不确定 / 尚未标定”提示。未启用通行组时，只显示分段触发，不生成速度。

后续多段协议至少需表达：段 ID、模式、布局或通行组关联、遮挡 / 恢复、设备采集时间、时钟归属、标定间距与估计有效性。具体字段与版本在初始化固件前再统一设计。

### 16.6 便携部署与开发顺序

“能挪动布局”“是否配立柱”和“各设备是否无电线”是不同要求。允许布低压线时，可先用集中供电、集中采集验证；若各设备必须独立供电并无线回传，再设计节点电池、同步和断链处理。立柱是否使用不决定电源和通信方案，此处仍保留两种路线。

建议先完成一段稳定检测，再用两段验证通行方向和时间采集，随后将同一检测段模型扩展到折线和闭合区域。单边验证阶段用于检验器件，不替代最终多场景目标。

待确认项：各设备是否必须独立供电和无线回传；目标最短 / 最长单段跨度；测速用于展示估算还是有明确误差指标；是否需要多高度防跨越；现场布设后是否接受手动对准与输入间距。

### 16.7 核心设备与安装附件分开配置

用户已明确：没有必要默认制作立柱，立柱可单独配置。

- 核心设备：红外发射 / 接收探头，以及所需的控制、电源和通信部分。探头与控制板是否合为一盒，待器件选型后确定。
- 基础安装需求：设备保留合适的固定位置和调角方式，可采用底座、安装孔或转接件；不提前写死具体螺纹和尺寸。
- 按场景选择附件：门框 / 墙面底座、栏杆夹具、绑带支架；无固定物的空地再选地插、三脚架或立柱。
- 已有树干等也可作为绑带固定位置，但需确认稳定性；松动枝条、会开合的门扇等不宜作为光轴基准。

设备可以小型化，光路仍需要稳定对准。调整安装位置后重新确认光束、高度与配置；测速组还要重新量两条检测线的间距。附件结构和实际外壳需一起验证防雨与固定效果。

组内交付时将电子设备清单与可选安装附件分列。软件中的段 ID 和布局不依赖立柱编号，无需立柱也能配置直线、折线、闭合围界或双线通行组。
